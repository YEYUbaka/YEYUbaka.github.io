# YEYUbaka 个人主页与个人网站设计

日期：2026-09-28  
状态：设计方向已确认，等待规格文档复核后实施

## 1. 目标

本项目同时解决两个公开展示问题：

1. 精简并重写 `YEYUbaka/YEYUbaka` 的 Profile README，使内容围绕“AI 专业学生、测试开发方向、Python 实践者”展开。
2. 新建 `YEYUbaka.github.io` 个人网站，以深色极简科技风展示个人定位、真实项目和学习方向。

两者共享同一套内容事实，但展示深度不同：README 负责快速建立认知，网站负责承载项目卡片和更完整的个人介绍。`LocalRAG` 是首版必须展示的核心项目，并作为项目列表的第一项。

## 2. 核心定位

主定位：

> AI 专业学生｜测试开发方向｜Python 实践者

辅助描述：

> 专注测试开发、Python 工程和 AI 应用实践，持续学习接口测试、自动化测试与测试工具开发。

定位使用规则：

- 面向测试开发岗位或项目合作时，优先强调接口测试、自动化测试和工具开发。
- 面向 AI 项目时，强调人工智能专业背景、Python 和 AI 应用实践。
- 不把“软件测试”作为主定位，不夸大为资深工程师或成熟开源贡献者。

## 3. Profile README 方案

### 3.1 信息结构

README 采用从定位到行动的六段结构：

1. **Hero**：姓名、英文技术标题、两行简介。
2. **Focus**：测试开发、Python、AI 应用三个方向。
3. **Selected Projects**：展示三个真实公开项目，每个项目只保留一句经过仓库 README 核验的描述和仓库链接；`LocalRAG` 固定排在第一位。
4. **Toolkit**：只保留正在使用或明确学习中的技术，按“开发、测试、数据/基础设施”分组。
5. **Currently**：当前学习重点和合作方向。
6. **Connect**：GitHub 和确认过的公开联系方式。

### 3.2 精简规则

- 删除空的工具分类和没有内容支撑的标题。
- 删除访客计数、Achievements、重复的活动图和过多统计图。
- 统计信息最多保留一个紧凑区域，并且不得成为页面视觉中心；首版可以完全不放统计图。
- Emoji 仅用于必要的视觉分隔，不用于每一行标题。
- 中英文混排只保留技术标题，主体说明使用简洁中文。

### 3.3 项目内容

首版项目展示固定为三个有明确 README 或功能描述的公开项目：

- `LocalRAG`：本地优先的 RAG 个人知识库系统，使用 React/Vite、FastAPI、ChromaDB、本地 Embedding/Reranker，以及向量检索与 BM25/RRF 混合检索。
- `AI-learning-companion`：基于 FastAPI 与 React 的 AI 个性化学习平台，支持智能学习计划、智能组卷、知识图谱与 AI 问答。
- `doubanspider`：豆瓣电影信息爬取、数据分析与可视化。

三个项目的描述只使用对应公开仓库当前可核验的内容，不加入未验证的性能数字或正式实验结论。

## 4. 个人网站方案

### 4.1 页面形态

首版采用单页滚动作品集，不拆分为多个路由。原因是当前目标是建立清晰的个人形象，单页能避免出现内容不足的空白页面，也便于 GitHub Pages 部署和维护。

页面区块顺序固定为：

1. **Hero**：`YEYUbaka`、测试开发与 AI 的主标题、简短定位、GitHub/项目入口。
2. **Focus**：测试开发、Python、AI 三个方向的短卡片。
3. **Selected Projects**：三张项目卡片，第一张固定为 `LocalRAG`，显示项目名称、定位、技术关键词和 GitHub 链接；没有公开演示地址时不伪造 Demo 按钮。
4. **Learning Path**：用简短时间线或列表表达接口测试、自动化测试、Python 工程和 AI 实践的当前学习路径。
5. **Contact**：GitHub、公开邮箱和后续可添加的外部链接。
6. **Footer**：版权和 GitHub 入口。

### 4.2 组件边界

建议将页面拆分为以下独立组件：

- `SiteHeader`：品牌、区块锚点、移动端菜单。
- `HeroSection`：首屏定位和主要行动按钮。
- `FocusSection`：三个方向卡片。
- `ProjectGrid` 与 `ProjectCard`：项目列表和项目卡片。
- `LearningSection`：当前学习路线。
- `ContactSection`：联系方式和外链。
- `SiteFooter`：页脚信息。

个人资料和项目内容放在独立数据文件中，组件只负责渲染。后续更新项目时只改数据，不重写布局。

### 4.3 视觉系统

- 背景：近黑色，避免纯黑造成死板对比。
- 面板：略亮于背景的深色表面，使用 1px 细边框和小幅阴影。
- 强调色：单一冰蓝或青蓝色，避免同时使用大量渐变色。
- 字体：中文使用系统无衬线字体，技术标签使用等宽字体。
- 布局：宽屏居中内容容器，移动端单列堆叠。
- 动效：首屏淡入、滚动进入、卡片微弱 spotlight；不使用大面积粒子、自动播放视频或持续闪烁。
- 可访问性：提供清晰的键盘焦点、足够的颜色对比、语义化标题和 `prefers-reduced-motion` 降级。

### 4.4 交互规则

- 顶部导航通过锚点滚动到页面区块。
- 主按钮进入项目区或打开 GitHub。
- 项目卡片整体可点击，但必须保留清晰的外部链接语义。
- 卡片 hover 只改变边框、光晕或轻微位移，不改变布局尺寸。
- 移动端导航使用可关闭的菜单，并支持 Escape 关闭。

## 5. 数据与真实性

内容来源按以下优先级处理：

1. 用户明确确认的个人定位和联系方式。
2. YEYUbaka GitHub 公开 Profile 和 Profile README。
3. 公开项目仓库的 README、AGENTS.md、代码结构和仓库元数据；其中 `LocalRAG` 使用 <https://github.com/YEYUbaka/LocalRAG> 作为项目入口。

统计图、项目 star 数、仓库数量等动态数据不作为首版核心内容，避免缓存过期或数据服务失效破坏页面。所有项目描述必须能在对应公开仓库中找到依据。

## 6. 实施范围

首版包含：

- 项目级 `AGENTS.md`。
- 精简后的 Profile README 草稿。
- `YEYUbaka.github.io` 单页前端项目。
- 响应式布局、基础动效、项目外链和 GitHub Pages 构建配置。
- 本地生产构建验证和浏览器检查。

首版不包含：

- 后台管理系统或 CMS。
- 登录、数据库、评论和表单后端。
- 没有真实内容支撑的简历页、奖项页或数据仪表盘。
- 自动抓取 GitHub 数据的运行时服务。
- 未经确认的远程仓库创建、推送或发布操作。

## 7. 验收标准

### README

- 首屏能够在几秒内表达“AI 专业学生、测试开发方向、Python 实践者”。
- 所有保留项目都有真实仓库链接和可核验的一句话描述。
- 不再出现空的分类标题、重复统计块和视觉噪音。
- 中英文标题、项目链接和联系方式在 GitHub Markdown 中正常渲染。

### 网站

- 桌面端和移动端均能完成首屏、项目区和联系方式浏览。
- 所有导航锚点、项目链接和 GitHub 链接可用。
- 生产构建成功，页面无明显控制台错误和 404 资源。
- 键盘可以访问主要交互元素；减少动态效果设置后页面仍然完整可用。
- 页面内容与 README 定位一致，不出现虚构经历或未经核验的项目描述。
